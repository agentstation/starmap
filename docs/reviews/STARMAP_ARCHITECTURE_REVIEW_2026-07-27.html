Architecture review · 27 July 2026

Starmap catalog architecture, upgrade lifecycle & simplification plan

Compared: 3787d716 → 9508ee78
Scope: catalog YAML, source flow, reconciliation, publication, DX

Verdict

The previous model was better in role, not in data quality.

The old local YAML had the clearer mental model: it was the catalog humans edited and updates wrote. The current catalog has richer records and much stronger immutable publication.

Important correction

There was no YAML migration to definitions or offerings.

/providers remains the stored tree. ModelDefinition and ProviderOffering were layered on as Go read models and synthesized during build.

Top risk

Editable YAML is currently treated like an export.

Once a durable generation exists, restart favors it and can ignore local YAML. That contradicts the intended operator workflow and makes two stores feel authoritative.

The provider tree is the single human authoring model. The generation is a compiled, validated read product. A newer embedded catalog is reconciled as low-authority evidence on explicit update—never copied wholesale over an existing workspace.

Do not add: /definitions, /offerings, /overrides. Machine metadata is state, not another configuration layer.

Upgrade and edit lifecycle

A new embedded catalog is evidence—not an overwrite

The lifecycle needs a three-way semantic comparison: current YAML, the last materialized value recorded in provenance, and the newly observed value. That gives the catalog module depth without introducing override files.

Binary upgrade: embedded revision E1 → E2

sequenceDiagram participant H as Human YAML workspace participant P as Persisted provenance participant E as New embedded revision E2 participant U as Update transaction participant C as Immutable Catalog Note over H,C: Installing the binary performs no implicit disk mutation U->>H: Read one consistent workspace snapshot U->>P: Load last emitted semantic values + source revisions U->>E: Verify manifest and payload digest U->>U: Classify changed YAML paths as local evidence U->>U: Reconcile E2 + local + live observations by one authority table U->>U: Validate complete candidate U->>H: Stage, fsync, compare input digest, atomic replace U->>C: Compile and atomically publish exact candidate

No workspace

Use or seed embedded

A read-only library can use verified embedded data in memory. The first explicit CLI update atomically creates the provider YAML tree and retains embedded provenance.

Workspace exists

Never silently rewrite at construction

Construction loads and validates the configured workspace. A newer embedded revision is reported as available and joins the next normal update transaction.

Store-only composition

No YAML dependency

A Starport process using only a catalog store publishes generations without touching ~/.starmap. Embedded supplies the empty-store baseline only.

How Starmap recognizes a human edit

Unchanged generated value

YAML equals the last provenance value. Keep its original provider, models.dev, or embedded source identity.

Semantic value changed

Only that field becomes local evidence. Dynamic valid facts may later outrank it; fields absent from sources remain manual.

Formatting-only change

Whitespace, key order, and quoting do not create evidence. Updates emit deterministic canonical YAML.

Explicit authoring contract: semantic values are preserved; comments, whitespace, quoting style, and key order are not durable product data. Human notes that must survive belong in a recognized field or controlled extension—not only in comments. This avoids a complex comment-preserving YAML merge implementation.

Strong recommendation

Restore one real local catalog path

P0–P1

client.go · sync.go · pkg/catalogs/catalog.go · pkg/catalogs/catalog_options.go · pkg/catalogs/load.go · pkg/catalogs/save.go · internal/catalog/pipeline

Before

Machine generations live at the path called “catalog”; editable YAML lives at an export path. Input/output resolution can diverge, and existing generations can mask manual edits.

After

One CatalogPath names the human YAML workspace and update is in-place. Machine state is internal or explicitly injected. Embedded seeds an absent workspace and later participates as versioned low-authority evidence.

Benefits: restores obvious DX, improves locality, removes path ambiguity, and keeps the compiled generation implementation free to be optimized independently.

Strong recommendation

Collapse authority and provenance into one executable implementation

P2

pkg/authority/authority.go · pkg/authority/canonical.go · pkg/reconciler/merger.go · pkg/provenance

Before

Two policy vocabularies coexist; the newer one is used only for pricing. Local still outranks dynamic evidence for some discoverable fields. Provider-scoped provenance can collide on a bare model ID.

After

One field-sensitive priority table selects winners and records evidence. Dynamic valid facts generally beat local fallback; operator connection configuration remains local-first. Provider facts key evidence by provider/model.

Benefits: one source of policy truth, explainable decisions, correct provider pricing, and no need for override files.

Strong recommendation

Make source updates non-destructive and YAML publication atomic

P4

pkg/reconciler/collector.go · internal/sources/providers/providers.go · pkg/catalogs/save.go · sync.go

Before

Absence from a provider listing can prune records; degraded observations can affect last-known-good state. YAML save removes managed trees before direct rewrites.

After

Absence is not deletion. Only validated explicit retirement evidence changes lifecycle. YAML is built in a staged sibling directory, synced, and atomically swapped.

Benefits: manual additions survive, partial provider failures cannot erase good data, and readers always observe a complete before/after workspace.

Execution control plane

Phased plan with verifiable gates

P0

Lock the catalog contract and characterize current behavior

Record /providers as the sole human model tree. Supersede—do not rewrite—historical export/legacy decisions.

  • Golden fixture contains no persisted definitions, offerings, or overrides.
  • Contract states that installing a binary never silently mutates an existing workspace.
  • Embedded, local, live, and release data are versioned observations—not overlay directories.
  • Exact old/current YAML comparison and operator journey become executable fixtures.
  • Tests reproduce store-only sync failure, path divergence, local merge loss, pruning, and non-atomic save before implementation.
P1

Make the local workspace real

  • Absent workspace is seeded from embedded exactly once; existing workspace is never silently overlaid.
  • A newer embedded revision is detected and reconciled on the next explicit update without a separate migration command.
  • Unchanged embedded-derived fields refresh; human-edited fields retain local provenance and beat embedded.
  • One catalog path is read and atomically updated in place; input and output cannot diverge.
  • Embedded construction cannot default to writing inside the repository.
  • Store-only library sync succeeds without a YAML destination.
  • Restart from written YAML produces the same catalog.
P2

Make reconciliation match the authority contract

  • One table governs all field selection; valid provider pricing wins atomically.
  • Dynamic facts replace local fallback; manual missing data and local-only configuration survive.
  • Comparing YAML to the last emitted provenance value marks only semantic human changes as local.
  • Explicit false/zero is distinguishable from absent/unknown.
  • Partial observations cannot delete or retire records.
  • Winner, provider/model scope, embedded revision, observation ID, checksum, reason, and rejected candidates survive restart.
P3

Keep one persisted model and derive immutable views

  • Durable payload remains provider-oriented; no definition/offering collections are persisted.
  • Same ID at two providers produces distinct offerings and prices.
  • FindModel is a deterministic provider-independent view using the same authority evidence—not alphabetical first-wins.
  • No exported “legacy migration” or LegacyV0 vocabulary remains pre-launch.
  • Catalog() remains non-failing, non-nil, O(1), allocation-free, and mutation-isolated.
P4

Prove non-destructive, atomic updates

  • A missing provider response never deletes a manual or last-known-good model.
  • Injected parse, fetch, validation, write, fsync, rename, commit, and publication failures retain a complete prior catalog.
  • A human edit made after candidate construction causes a digest conflict; it is never overwritten.
  • One workspace lock prevents two processes from interleaving updates.
  • Concurrent readers observe exactly one complete generation before or after publication.
  • Recovery semantics are explicit when YAML materialization and generation commit cannot both complete.
P5

Delete duplicate data and unused implementations

  • No author model files are loaded, written, embedded, or stored in payloads; derived author queries remain equivalent.
  • No production imports remain for each deleted module.
  • Public exports, package count, production Go LOC, embedded bytes, and binary size are reported before/after.
  • Scheduler/server remain only after an explicit named product composition is documented.
P6

Prove the human and Starport workflows

  1. Seed an absent catalog from embedded.
  2. Add a private manual provider/model and a missing field to an existing model.
  3. Upgrade to a binary with embedded E2; confirm unchanged E1-derived values refresh and the manual edit survives.
  4. Fetch conflicting current data plus a degraded source; confirm authoritative dynamic values win and manual gaps survive.
  5. Inspect provenance for every winner, restart, and obtain identical results.
  6. Race two writers, roll back, attempt an incompatible downgrade, and reject a tampered artifact.
  7. Run exact Go toolchain verification, race suite, fault suite, vet/lint/docs, diff check, accessor benchmark, and release artifact roundtrip.

Top recommendation

Start with P0 and P1: lock the upgrade contract and restore one editable provider catalog.

Do not revert the current rich YAML, immutable catalog, provider indexes, or atomic generation publication. Make /providers the sole persisted human model. Treat every new embedded catalog as verified, low-authority evidence on explicit update—not a wholesale overlay—and make generations compiled products of the exact reconciled workspace.

Why first: until local YAML is genuinely the editable workspace and binary upgrades have deterministic merge semantics, every later provenance, scheduling, distribution, and source feature is being composed around the wrong operational contract.
