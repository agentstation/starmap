Catalog distribution plan

Status: active. Owner: this plan. Created: 2026-09-01. Baseline: main @ 42b610a, publisher work @ 6c7edfbe, Starport main @ 117ad8f5. Proof root: docs/proof/catalog-publisher/. Next action: start CAT2.1 and select the native Go attestation verifier dependency.

Outcome

Starmap publishes and embeds the Starmap public catalog. One connected runtime composes the embedded catalog, a selected upstream catalog, and operator observations into an effective catalog. Starport consumes that catalog locally or from a shared enterprise Starmap server.

Progress

The status ledger supplies progress.

Architecture

Scope

Owns: publisher credentials and cadence, catalog names, the public channel, GitHub verification, and catalog-source contracts.

The plan also owns connected runtimes, application defaults, source cascading, Starport adoption, migration guidance, proof, and releases.

Does not own: provider inference credentials, provider account creation, a managed AgentStation Starmap deployment, or enterprise network and storage provisioning.

Non-goals: do not change provider fact authority without an owner decision. Do not expose secrets or trust mutable tags. Do not require GitHub CLI in a Go consumer.

Invariants

Security and trust

  1. No secret value enters Git, logs, plans, proof files, or replies.
  2. The workflow exposes provider credentials only to its refresh step.
  3. The mutable channel can select only an immutable verified catalog release.
  4. Every activation verifies publisher identity, bytes, schema, and generation order.
  5. A failed source retains last-known-good state and reports degradation.

Runtime behavior

  1. A configured enterprise source causes no undeclared public GitHub fallback.
  2. The low-level catalog client remains safe for deterministic offline use.
  3. Starport validates a complete runtime candidate before acceptance.
  4. Existing catalog releases remain immutable and readable.
  5. Each background lifecycle has one owner and a bounded shutdown.
  6. One runtime retains all input layers and owns effective catalog publication.

Acquisition behavior

  1. A missing catalog-acquisition credential is neutral and causes no provider request.
  2. Provider failures retain unrelated provider observations and effective facts.
  3. A progressing bounded transfer is not canceled by an arbitrary elapsed-time default.
  4. Automatic work uses stable fleet phases, retry not-before, admission control, and one owner for shared state.
  5. A transfer has a total bound derived from its size cap and a floor rate, and no stage waits without a bound.
  6. Catalog-acquisition credentials come only from the deployment lookup, never from the inference keyring.

Decisions

Runtime and naming

CAT-D1, accepted 2026-09-01: New releases use catalog-<digest>, discovery uses catalog-latest, and only technical checksum fields use semantic terminology.

CAT-D2, accepted 2026-09-01: Keep starmap.New offline, and make starmap.Open the connected API with narrow Catalog, State, and Status reads.

CAT-D3, accepted 2026-09-01: Use independent source and acquisition policies that retain each layer and treat operator model observations as additive, not entitlement evidence.

CAT-D4, accepted 2026-09-01: Support public, github, starmap, file, and embedded sources without public fallback from a custom source.

CAT-D5, accepted 2026-09-01: Use fast prefer_source startup, last-known-good fallback, one-hour GitHub polling, and Starmap SSE with conditional polling fallback.

Acquisition decisions

CAT-D6, provisional engineering selection: Use sigstore-go behind Starmap-owned GitHub identity and transport policy, subject to CAT2.1 evidence and GitHub CLI parity.

CAT-D7, accepted 2026-09-01: Give Starport one Starmap runtime, default its source to public, enable credential-detected acquisition, and preserve its accepted head.

CAT-D8, accepted 2026-09-01: Remove the acquisition mode, enable automatic acquisition by default at a four-hour interval in both applications, and keep explicit Sync.

Publication decisions

CAT-D9, accepted 2026-09-01: Advance an attested channel sequence and channel_updated_at after every successful four-hour verification without a no-change catalog generation.

CAT-D10, accepted 2026-09-01: Publish every four hours at minute 17 and poll consumers every hour. Use a six-hour end-to-end freshness objective.

Automatic policy decision

CAT-D11, accepted 2026-09-01: Use CATALOG_ACQUISITION_ENABLED plus INTERVAL. A false enabled value disables all automatic work, and no periodic-only state exists.

CAT-D12, audited 2026-09-01: Bound connect, TLS, headers, transfer inactivity, bytes, pages, and records. Add no whole-refresh deadline by default. Use a 60-minute publisher job limit.

CAT-D13, audited 2026-09-01: Use full-interval stable phases, a 15-minute cold-start spread, one-second to 15-minute decorrelated retry, retry not-before, source admission, and a distributed refresh lease.

Contract and transport decisions

CAT-D14, audited 2026-09-02: The runtime has one Sync(ctx, ...SyncOption) (AcquisitionReport, error) method. Close is idempotent and joins runtime-owned work within five seconds.

CAT-D15, audited 2026-09-02: Each transfer has a maximum duration equal to its size cap at a 256 Kbps floor rate, with a 60-minute default. A Starmap-owned transport wrapper applies the 60-second header bound to every catalog request, including the SSE open. Peak memory is one buffered body per in-flight transfer.

Fleet and dependency decisions

CAT-D16, audited 2026-09-02: Direct GitHub consumption stops at 60 unauthenticated instances per address and near 5,000 per token. Status warns at 80 percent of the reported rate limit. The six-hour objective applies to direct consumers and SSE-push chains. Each polling hop adds one poll interval.

CAT-D17, audited 2026-09-02: CAT8 pins a Starmap pseudo-version from the plan branch. CAT11 replaces the pin with the released tag.
