# CSP18 decisions

Date: 2026-10-03. The lead made decisions 18-1 through 18-10 inside the accepted task scope. They follow the engineering specification sections 10.2 and 10.3. The owner can reverse any of them before the final acceptance run. The discovery record is `DISCOVERY.md`. The fail-before proof is `../fail-before-2026-10-03/`.

| ID | Decision | Reason and consequence |
| --- | --- | --- |
| 18-1 | CSP18 prepares the Pages artifact and a manual, protected deployment workflow. It does not enable Pages, does not create the environment, and does not run the workflow. | The task says "prepare". The repository has no Pages site and no environment. A publication is an outward-facing release action that needs separate authorization. CSP23 supplies the public-URL evidence. |
| 18-2 | Version paths are `/<release>/` per tag plus a `/latest/` alias. The deployment reassembles earlier releases from the docs release assets, because a Pages deployment replaces the whole site. Rollback redeploys an earlier docs asset. | The specification names stable `/<release>/` paths and prior-release retention. A per-minor path would let patch releases overwrite each other and weaken the A29 content-manifest comparison. |
| 18-3 | The docs build reuses the console toolchain: Vite, React, and unified (remark and rehype) over a Markdown content tree. A Node build step prerenders one static HTML page per topic into `internal/console/dist/docs/` with a small client script for search, the current-section marker, theme, and copy controls. The search index is a MiniSearch index built at build time from headings, prose, and setting names. No Starlight, Docusaurus, or Pagefind. | One toolchain, one token set, and the existing contrast tests apply. The console CSP is same-origin, and a prebuilt JSON index needs no WebAssembly and no runtime fetch outside the docs tree. Prerendered pages work on Pages, from an exported directory, and without JavaScript, which the recovery case needs. The limit is custom code for the table of contents, the version display, and the prerender step. |
| 18-4 | One Markdown content tree under `docs/site/` in Starport is the single source for the embedded docs and the public site. It holds the nine specification areas. The existing repository Markdown files stay in place in CSP18. Topic pages link to repository files at the released tag, never at `main`. | The specification requires one authored tree that builds both outputs. Moving the 5,617 lines of repository Markdown would change five verification scripts and the identity link, which is out of scope. CSP19 and CSP20 own the recipes and the README. |
| 18-5 | The static site replaces the React `/docs` route. The gateway serves `/docs/` from the embedded build without a session. The console navigation uses a full-page link. The CPL conditions V44 and V45 keep their intent and count, re-pointed to the static recovery source and its test. | A client-routed page cannot serve the recovery case or a static host. The CPL gate requires the health endpoints in the recovery text and a test over it. The pull request lists the two re-pointed conditions. |
| 18-6 | The embedded docs make no request to an API, configuration, or session endpoint. Generated reference pages come from descriptors at build time and hold no deployment value. A Go test serves the docs without a session and proves the dynamic endpoints still refuse. | A29 requires docs without credentials, catalog readiness, or internet. The specification keeps dynamic deployment data behind authorization. |
| 18-7 | The release attaches `starport-docs-<tag>.tar.gz`, the exact static artifact, through goreleaser. `starport docs export <dir>` writes the embedded tree to disk. Both come from one build output. | The specification keeps the exact static artifact as a release asset for offline export and rollback. The command serves an operator whose gateway fails after the binary starts. The release-archive and release-workflow verification scripts must accept the new asset. |
| 18-8 | The A30 browser subcases use a `reviewed_ui` proof whose required inputs are the docs shell, styles, build configuration, and one representative topic, not the whole content tree. Structural facts (anchors on every heading, table of contents, skip link, landmarks, history) have jsdom tests. The lead performs the browser review with a real browser against a local gateway build. The same record renews E01. | The verifier has no automated browser kind, and a new kind is a Starmap verifier change with a CI browser. A proof bound to the shell stays valid across content edits. The limit: a shell or style edit invalidates the proof, and the next task that edits the shell renews it. |
| 18-9 | The generated settings inventory covers the Starmap descriptors from `ConfigurationSchema()` and the Starport environment settings reflected from the `Config` struct env tags (name, section, type, default). The generated file inventory comes from `FileManifest` per platform. Tests fail when a generated page is stale. | The specification names the pinned Starmap settings contract and Starport descriptors. The env tags are the Starport descriptor source today. Prose for each Starport setting stays in the authored Configure and Operate pages. |
| 18-10 | The content covers the discovery audit topics and the unrecognized-journal guidance. The discovery pages report readiness as a fixed unknown, per CSP17 decision 17-7, and name the released Starmap dependency for canonical reconciliation. | The discovery audit contract DR07 and the CSP2 record assign these topics to CSP18. |

## Delivery slices

1. Content tree, build, prerender, and search. Anchors, table of contents, version display, serving, and navigation. Target subcases: `A29.embedded_offline_search`, `A30.stable_links_history`.
2. Generated settings and file inventories, `starport docs export`, and the docs release asset. The no-session serving test, the discovery and journal content, and the pinned identity link. Target subcases: `A29.recovery_without_auth`, `A29.no_dynamic_data_disclosure`.
3. Accessibility work, the browser proof, the Pages artifact with its content manifest, the prepared workflow, and the Starmap registry change. Target subcases: the four A30 browser subcases and the gate.
