# Discovery audit task criteria

These criteria extend the existing plan tasks and acceptance subcases. They create no new plan or acceptance credit.
The [independent verification](verification.json) retains the current defects and candidate results.

## CSP3

Repeat atomic pricing, explicit-zero, and metadata-only linked membership tests through canonical runtime reconstruction. Preserve D24 resets and D25 scope links.

## CSP8

The committed module must compile catalog tests and carry canonical pricing and membership fixes. Repeat provider and non-provider acquisition through startup, refresh, restart, and Starport projections. A temporary workspace substitution cannot qualify the pin.

## CSP10

Separate accepted catalog, permitted discovery, structural support, and caller readiness. Preserve discovery without operator keys and redact prohibited membership. Verify each compatibility route against its declared membership contract.

## CSP10.1

Precompute definition and offering discovery indexes. Keep caller policy and credential state as bounded current filters. Avoid provider or secret-manager calls during catalog listing.

## CSP10.2

Use current caller scope for discovery and readiness. Recheck policy on cached delivery, retries, and batches. Cover personal credentials and shared grants independently of operator keys.

## CSP12.1

Warm the production discovery cache before adapter removal and restoration at an unchanged catalog generation. Verify model, provider, and endpoint results. Prove actual endpoint cache hits. Cover restart identities, replica collisions, caller isolation, and known withdrawals.

## CSP17

Explore preserves permitted membership without usable credentials. Provider facets count distinct offering providers and agree with URL filters. Author facets remain separate. Chat defaults and comparison actions explain operation and caller readiness across J1 through J3.

## CSP18

Explain permitted discovery, structural support, caller readiness, and cache freshness in embedded and public documentation. Name the released dependency that supplies canonical reconciliation.

## CSP20

Explain catalog browsing before credentials and distinguish it from a successful caller-authorized inference request.

## CSP21

Record discovery without credentials, an appropriate setup action, and caller-ready streaming from the same declared release pair.

## CSP22

Repeat the discovery audit through HTTP, browser journeys, current caller policy, replicas, and the declared release candidate.

## CSP24

Confirm discovery, caller readiness, pricing, and cache dependency behavior from shipped assets after upgrade and restart.
