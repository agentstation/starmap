# Passive retained catalog permission

Structural runtime inspection does not establish current admission permission. The recovery coordinator needs a separate owner check before component release and final SQL approval.

Add a passive Starmap capability over the selected accepted authority head, configured source policy, original native runtime identity and seed, and exact retained permission checkpoint. Use the existing authority permission state transitions and receipt expiry rule. Ordinary selected catalogs require no qualified UTC. Internal authority receipts require a qualified current clock sample.

Read existing files only. Do not construct a connected runtime, acquire sources or credentials, publish a checkpoint, clear uncertainty, renew a receipt, or change validation time. Missing, corrupt, uncertain, expired, mismatched or withdrawn authority evidence refuses permission. Rechecks preserve the original checkpoint bytes and native identity. The host checks exact catalog selection and its complete recovery decision separately.

A crash checkpoint remains uncertain. Recovery requires separately verified source-owner evidence before permission can resume. The passive inspector must report that need instead of treating a cache TTL as authoritative expiry.
