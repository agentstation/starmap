Strict technical writing plan

Status: active. Owner: this plan. Created: 2026-08-30. Baselines: Starmap main@b36d8041, skills main@dd86deda. Proof root: docs/plans/proof/strict-technical-writing/. Next action: publish, merge, and clean up the final pull request for TW9.

Outcome

Starmap keeps one reviewed glossary and one strict writing policy. Every maintained document and source comment passes the strict linter. The shared linter skips generated artifacts through tested content markers.

Progress

The status ledger supplies the progress value.

Architecture

Scope

Owns: generated-artifact detection in the shared skill, the Starmap glossary and policy, and all maintained Starmap prose.

The scope also includes source comments, test comments, generated documentation refresh, and repository verification.

Does not own: historical files under docs/reviews/**, third-party legal text, or catalog descriptions stored as structured data.

Non-goals: no Go behavior, public API, wire format, catalog fact, dependency, or release change.

Invariants

  1. Each rewrite preserves the source fact, condition, value, identifier, and confidence.
  2. Strict mode passes without a broad rule suppression.
  3. Each exclusion names content that the repository does not maintain as technical prose.
  4. Generated documentation changes only through its source and generator.
  5. Go edits preserve behavior and satisfy the resolved ago policy.
  6. Existing uncommitted Starmap changes remain attributed and intact.
